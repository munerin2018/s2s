# 制約

完全 P2P にすると、中央サーバーが黙って引き受けていた仕事が全部こちらに返ってきます。
ここでは **「設計上そういうもの」** と **「今は未実装」** を分けて書きます。
前者を隠すと、後から中央サーバーを足すことになります。

---

## 設計上そうなるもの

### オフラインの相手の投稿は見えない

Twitter はサーバーが投稿を持ち続けます。S2S にはそれがありません。
ある人の投稿が見えるのは、**その人か、その人のログを複製した誰かがオンラインのとき**だけです。

やわらげる方法は「常時起動のピアを1つ持つ」ことです。
`scripts/peer.js` や `rust/s2s-peer` はそのためにあります。
ただしそれは**あなたが選んで置いたピア**であって、全員が依存する中心ではありません。

### 誰も持たなくなったメディアは消える

投稿本体はハッシュしか持っていません。実体を持つピアが1つもいなくなれば、取得できなくなります。
人気のある画像は多くのピアに複製されるので残り、誰も見なかった画像は消えます。

これは IPFS の pinning と同じ問題です。永続化したいなら、自分で持ち続けるしかありません。

### 検索は手元にあるものだけ

全世界のピアに問い合わせることはできません。
検索できるのは、すでにあなたの端末に複製されているイベントだけです。

分散全文索引は可能ですが、索引を誰がどう持つかという別の設計問題になります。

### 鍵を失うとアカウントは戻らない

パスワード再発行をしてくれる主体が存在しません。
設定タブの「秘密鍵を表示する」から控えを取っておいてください。

Web 版はブラウザのサイトデータを消すと鍵も消えます。

### 削除は「お願い」でしかない

`delete` は墓標です。受け取ったピアは表示をやめますが、
すでに複製された生のイベントを物理的に消す方法はありません。
**一度ネットワークに出したものは取り消せない**と考えてください。

### ブラウザとスマホは自力で他のピアを見つけられない

ポートを開けず mDNS も話せないため、最初の1つは人間が教える必要があります。
PC 版のアドレスを貼るか、`#peer=` 付きの URL を開くか、です。

## 今は未実装

正直に言うと、ここから先は作れば直るものです。

### スパムと Sybil 攻撃

今あるのは**ブロックだけ**です。鍵はいくらでも作れるので、
本気で荒らされたら手が足りません。中央サーバーなら IP 制限や BAN ができますが、ここではできません。

考えられる方向：
- フォローグラフからの距離で表示を制限する（SSB がやっている方式）
- 信頼できる人がブロックした相手を自動的に弱く扱う
- 投稿に軽い proof-of-work を課す

### ユーザー発見

現状「知っている人」は、接続したピアが持っていた人だけです。
知らない人を探す手段がありません。

Kademlia DHT は `--dht` で有効にできますが、発見機能としてはまだ使っていません。

### 大規模化

今は**全イベントを1つのゴシップトピックに流しています**。
参加者が増えたら破綻します。本来は、

- フォローしている人ごと / 板ごとにトピックを分ける
- 興味のあるものだけ購読する

とすべきです。板ごとのトピック（`s2s/v1/board/<板名>`）は用意だけしてあります。

### ログの刈り込み

ログは追記専用で、消えません。何年も使うと端末が埋まります。
古い部分を捨てても連鎖が壊れないようにする仕組み（チェックポイント）が要ります。

### 同時編集

プロフィールのような「最新が勝つ」データは、今は単純に `ts` が新しい方を採用しています。
複数端末で同じアカウントを使うと、素朴に上書きされます。CRDT を入れるならここです。

### 複数端末で同じアカウント

**今はできません。** `seq` が衝突してフォーク扱いになります。
端末ごとに副鍵を作って1つの人格に束ねる設計が必要です。

## 安全性について

やってあること：

- すべてのイベントは ed25519 署名で、偽造できません
- `id` が署名まで含めてハッシュしているので、署名の差し替えができません
- ログはハッシュ連鎖で、過去の改竄が検出できます
- メディアは内容ハッシュで名前がついていて、偽物を掴まされません
- 同じ `seq` の二重署名（フォーク）を検出します
- **blob id は必ずデコードして再エンコードしてから使います**（パストラバーサル対策）
- **have ベクタ・イベント・ゴシップの中身はすべて型と範囲を検証します**
- 受信バッファには著者ごとと全体の両方に上限があります
- 同時ストリーム数とタイムアウトに上限があります
- 検証を通ったイベントは、定義されたフィールドだけで作り直してから転送します
- **`delete` は対象の著者を確認できるまで保留します**（先回りによる検閲対策）
- 同一著者への書き込みは直列化されます（フォーク検出のすり抜け対策）
- Web 版には CSP が入っていて、第三者スクリプトが動きません

やっていないこと：

- 投稿の暗号化（**すべての投稿は公開です**。DM はありません）
- メタデータの秘匿（誰と接続しているかは相手に分かります）
- 実行時のレート制限（接続あたりの帯域・頻度に上限がありません）
- フォークの自動修復（検出して拒否するだけです）

### 悪意あるピアを想定したテスト

正常系のテストでは、上に挙げたものはどれも見つかりません。
プロトコルに従わないピアを模したテストが別にあります。

- `packages/core/test/hostile.test.js`
- `rust/s2s-peer/src/store.rs` の `mod tests`

パストラバーサル、先回りした `delete`、並行する同一 `seq` の書き込み、
使い捨て鍵による保留バッファの膨張、不正な have ベクタなどを扱っています。
**機能を足すときは、ここにも1件足してください。**
