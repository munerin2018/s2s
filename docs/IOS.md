# iOS

iOS には 2 つの道があります。**ほとんどの人には 1 つ目で十分です。**

---

## 1. ホーム画面に追加する（推奨・無料）

Safari で [Web 版](https://munerin2018.github.io/s2s/app/) を開き、共有ボタンから
「ホーム画面に追加」。それだけです。

アイコンが並び、次からはアドレスバーのない全画面で開きます。
アカウントの鍵はその端末の中だけに作られ、どこにも送られません。

PC 版とつなぐには、**PC 版の「設定」タブに出ている QR コードを iPhone の標準カメラで読みます。**
アプリが開いて、そのまま繋がります。長いアドレスを手で打つ必要はありません。

### なぜこれで動くのか

ここが一番の技術的な肝なので書いておきます。

**https のページは `ws://` に接続できません。** ブラウザが無条件に拒否します。
ホーム画面に追加した Web 版は中身が Safari のページなので https で動いており、
PC 版が開いている WebSocket のアドレスには**原理的に繋がりません**。
`wss://` にするには証明書が要りますが、家庭内 LAN の PC に証明書はありません。

そこで **WebRTC Direct** を使っています。
これは接続先の自己署名証明書のハッシュ（`certhash`）をアドレス自体に埋め込む方式で、
認証局も独自ドメインも要らず、mixed content の制約も受けません。

```
/ip4/192.168.0.16/udp/4003/webrtc-direct/certhash/uEiAYdfa0...  /p2p/12D3KooW...
                                          ~~~~~~~~~~~~~~~~~~~
                                          これがあるから繋がる
```

PC 版はこのアドレスを起動のたびに変えないよう、**libp2p の鍵と WebRTC の証明書を
ディスクに保存**しています。保存しないと再起動のたびにアドレスが変わり、
一度ペアリングした iPhone が繋がらなくなります。

### iPhone だからこその制約

| | |
|---|---|
| **保存データが消えることがある** | iOS はしばらく使われていない Web アプリのデータを自分で削除することがあります。**消えるとアカウントは戻りません。** 設定タブの「秘密鍵を表示する」から必ず控えてください |
| **閉じている間は同期しない** | iOS は Web アプリをバックグラウンドで動かし続けません。開いている間だけ繋がります（Android の Web 版も同じ） |
| **自動発見ができない** | mDNS はブラウザから使えないので、最初の 1 回だけ QR で PC 版を教えます |

最初の 1 つは本当に注意してください。**鍵のバックアップが唯一の保険です。**

## 2. ネイティブアプリとしてビルドする

**Mac と Xcode が必要です。** Windows や Linux ではビルドできません（Apple の制約）。

```bash
npm install
npm run build:web
npx cap add ios          # 初回のみ。ios/ プロジェクトを生成します
npx cap copy ios
npx cap open ios         # Xcode が開きます
```

Xcode で実機を選んで実行します。

### それでも Apple のアカウントは要ります

| | |
|---|---|
| **無料の Apple ID** | 自分の端末に入れられますが、**7 日で期限切れ**になり、その都度入れ直しです |
| **Apple Developer Program（年 99 ドル）** | 期限切れなし。TestFlight や App Store での配布も可能 |

この「維持費ゼロ」を掲げたプロジェクトで年 99 ドルを前提にはできないので、
**リリースに iOS のビルドは含めていません。** 1 つ目の方法を使ってください。

`ios/` ディレクトリは `android/` と同じく生成物としてリポジトリに含めていません。
上のコマンドでいつでも作り直せます。

### ネイティブ版だけの利点

正直に言うと、そこまで多くありません。

- WebView の設定で `ws://` を許可できるため、WebRTC Direct ではなく WebSocket でも繋がる
- アプリとして扱われるので、iOS によるデータ削除の対象になりにくい
- プッシュ通知（現状このアプリは使っていません）

2 つ目は鍵の保全という点で意味がありますが、
**どちらにせよバックアップは取るべき**なので、決定的な差ではありません。

## 動作確認について

正直に書いておきます。

- **WebRTC Direct でブラウザから PC 版に繋がることは、実際のブラウザ（Chromium）で確認済みです。**
  投稿が双方向に同期することまで見ています。
- **ただし iPhone 実機での確認はできていません。** 開発に使った環境に iOS 端末がありませんでした。
  Safari は WebRTC と IndexedDB に対応しており、使っている機能はどれも標準の範囲内ですが、
  「動くはず」であって「動いたのを見た」ではありません。

うまくいかない場合は [Issue](https://github.com/munerin2018/s2s/issues) をください。
Safari の Web インスペクタ（Mac と USB 接続が必要）でログが見られると、原因がすぐ分かります。
